# mosaico — LLM-агентная платформа (Delimobil, прод)

Аналитический и HR-чатботы для сотрудников компании на общей агентской платформе. Отвечал за полный цикл: архитектура, backend, гардрейлы, тестирование, поэтапная раскатка, интеграции. ~6k строк Python 3.11 + ~7k строк тестов.

## Архитектура

- **FastAPI, полностью async:** async PostgreSQL (psycopg3 + пул соединений), httpx AsyncClient; синхронные драйверы (Vertica, LDAP) изолированы через `asyncio.to_thread` + Semaphore.
- **Слоистая архитектура портов/адаптеров** (core / links / domain / logic / facade) со строгими правилами зависимостей, задокументирована в arch-документе. DI по типу-аннотации через `inspect.signature`.
- **Transport-agnostic агенты:** единый контракт `Agent`, три транспорта поверх одного кода — OpenAI-совместимый API, корпоративный мессенджер eXpress (pybotx), собственный MCP-сервер (StreamableHTTP + OAuth). Одного и того же агента можно дёргать из OpenWebUI и из мессенджера.
- **Агентский стек:** langchain / LangGraph + MCP-инструменты.

## Безопасность

- **Sandbox исполнения кода:** агент умеет выполнять сгенерированный Python — каждый вызов в эфемерном Docker-контейнере (`docker run --rm`, DinD): `--network none`, лимиты memory/cpu/pids, read-only ФС + tmpfs, таймаут с принудительным kill. Абстракция runner'а (dev-режим без изоляции / прод с изоляцией), сессии с namespace и TTL-очисткой, публикация артефактов, тесты.
- **Собственный слой авторизации:** Keycloak — OIDC, JWT/JWKS, RS256.
- Ограничения исполняет среда запуска агента.

## Интеграции с корпоративным контуром

Active Directory (ldap3/LDAPS), Keycloak, Confluence (REST), 1С (REST), Vertica, eXpress-боты.

## Тестопригодность

Внешние клиенты — на ABC/Protocol; для каждого пара «реальная реализация + Mock», contract-тесты; ~7k строк тестов (≈1:1 к коду), pytest + pytest-asyncio, e2e через docker compose. Интерфейсы и моки также помогают при разработке с LLM-агентами: сгенерированный код обычно требует мало правок.

## Поставка

GitLab CI (build → test → deploy), Docker, зависимости через uv, логи в Kibana. Деплой в k8s (werf + Helm — на стороне devops; докеризация и архитектура сервиса — мои).

## Границы

Это единственное агентское прод-приложение (два бота на общей основе); больших мультиагентных оркестраций в проде не строил — задача не требовала.
