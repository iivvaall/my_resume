**mosaico — LLM-агентная платформа (backend, ~6k строк Python 3.11):**
- FastAPI, полностью async: async PostgreSQL (psycopg3 + пул соединений), httpx AsyncClient; синхронные драйверы (Vertica, LDAP) изолированы через `asyncio.to_thread` + Semaphore.
- Слоистая архитектура портов/адаптеров (core / links / domain / logic / facade) со строгими правилами зависимостей; DI по типу-аннотации через `inspect.signature`.
- Тестопригодность как принцип: внешние клиенты — на ABC/Protocol, для каждого пара «реальная реализация + Mock», contract-тесты; ~7k строк тестов (≈1:1 к коду), pytest + pytest-asyncio, e2e через docker compose.
- Интеграция с корпоративной инфраструктурой: Active Directory (ldap3/LDAPS), Keycloak (OIDC, JWT/JWKS, RS256 — собственный слой авторизации), Confluence (REST), 1С (REST), Vertica, eXpress-боты (pybotx).
- Transport-agnostic агенты: единый контракт `Agent`, три транспорта поверх одного кода — OpenAI-совместимый API, eXpress, собственный MCP-сервер (StreamableHTTP + OAuth).
- Sandbox исполнения кода: отдельный сервис, дочерние Docker-контейнеры с network none, ресурсными лимитами и таймаутом.
- Докеризация и CI: GitLab CI (build → test → deploy), зависимости через uv, логи в Kibana.

**cvfront + models_server — инференс-платформа:**
- Двухуровневый сервинг: FastAPI-фронт (CPU-препроцессинг + бизнес-логика) → TorchServe-бэкенд (CPU/GPU-инференс) по REST.
- cvfront: FastAPI + uvicorn (ASGI, мультипроцесс), pydantic; тонкий сабкласс uvicorn-супервизора — свой liveness-таймаут воркера + логирование; контроль конкурентности; ~15 эндпоинтов. Структурированные JSON-логи с `request_id` через contextvars.
- models_server: TorchServe с кастомными хендлерами (torchscript / YOLO), CPU и GPU инференс (выбор устройства, батчинг per-model), Prometheus-метрики, клиент с retry/timeout.
- CI для моделей: GitLab CI, мульти-стейдж Docker, `torch-model-archiver`, pytest+junit, версия из `CI_PIPELINE_IID`, выкат в 3 странах × stg/prd. Общий внутренний пакет через приватный GitLab pypi.
- Нагрузочное профилирование инференса (самописный бенчмарк: 50 параллельных клиентов, per-request латентность и RPS) — подбор числа воркеров, `batch_size`, `max_batch_delay`; отдельно вклад препроцессинга и «чистой сети», CPU vs GPU.

**spare — парсинг заказ-нарядов (обработка данных):**
- Самостоятельная реконструкция табличной сетки из векторных PDF-примитивов (pdfminer + pdfplumber + shapely: STRtree, union/difference, buffer). Собственный алгоритм слияния коллинеарных отрезков + snap концов; карта инцидентности достраивает недостающие линии сетки.
- «Грамматика документа» на парсер-комбинаторах (funcparserlib): геометрия → поток токенов → regexp-теги → грамматика с 5 альтернативными layout-версиями.
- DVC-пайплайн, `multiprocessing.Pool`, golden-тесты на реальных документах, GitLab CI + Docker.

**ML (как плюс — коротко):** NLP-классификация на transformers (focal loss, k-fold, DVC, DI-контейнеры), CV on-device (TFLite, CI с численной сверкой), uplift-pricing, causal (Double ML).
