# Домен: MLOps / ML-инфраструктура

## Ключевой факт

В Delimobil построил MLOps-инфраструктуру команды **с нуля** и держу на ней стандарт «от постановки задачи до осязаемого baseline — 2 недели». Для лида это множитель: снижается time-to-value по любой гипотезе, а не по одной модели.

## Что построено (Delimobil)

- **Воспроизводимость:** git + DVC для кода, данных и моделей; эксперименты — DVC-пайплайны; претрейны из локального DVC-зеркала (загрузка «из интернета в момент обучения» исключена).
- **One-click деплой** и гарантия соответствия prod-модели тестируемой: CI собирает, тестирует и публикует модель одним пайплайном; версия из `CI_PIPELINE_IID`.
- **Численная сверка на краях:** для on-device моделей CI включает экспортный бандл + unit-тесты на стороне мобильного приложения — выход модели на тестовых картинках численно совпадает с питоновским (ловит расхождения препроцессинга, например разность resize).
- **Инференс-платформа:** FastAPI-фронт + TorchServe (CPU/GPU), кастомные хендлеры, батчинг per-model, Prometheus-метрики, структурированные JSON-логи с request_id; выкат в 3 странах × stg/prd. → [projects/inference-platform.md](../projects/inference-platform.md)
- **Нагрузочное профилирование:** самописный бенчмарк (50 параллельных клиентов, per-request латентность, RPS) для подбора числа воркеров, batch_size, max_batch_delay; отдельно вклад препроцессинга vs «чистой сети», CPU vs GPU.
- **Общие пакеты** через приватный GitLab PyPI; зависимости через uv; шаблоны пайплайнов для новых экспериментов.

## Мониторинг

- Grafana-мониторинг моделей и пайплайнов (Сбермегамаркет): метрики на валидации + технические сигналы для ранней ловли фейлов.
- Prometheus-метрики инференса (Delimobil).
- Для on-device модели налажен забор отклонённых фото с мобилки — задел под переразметку и дообучение; регулярного автоматического мониторинга качества в проде пока нет (честная формулировка).

## Kubernetes / Helm

Сервисы деплоятся в k8s: докеризация и архитектура сервиса — мои, Helm-чарты писал точечно (werf/Helm в основном держит devops). Гэп — эксплуатация кластера, не K8s как деплой-модель.

## Границы опыта (честно)

- Feature store, online-фичи и стриминговый инференс в проде не эксплуатировал; прод-опыт — batch + синхронный serving (REST) + edge.
- Специализированные ML-платформы (Kubeflow, SageMaker, MLflow как прод-реестр) не внедрял — инфраструктура строилась на git+DVC+GitLab CI, что для команды размера 2–6 человек было осознанным выбором.
