# Домен: LLM / NLP

## Ключевой факт

Агентское приложение в проде — полный цикл: аналитический и HR-чатботы на общей платформе ([mosaico](../projects/mosaico-llm-agents.md), langchain + MCP). Архитектура, прод-гардрейлы, тестирование, поэтапная раскатка, интеграции с внутренними системами.

## Дифференциация

К LLM пришёл из прод-инженерии (CI/CD, Airflow, sandbox-инфраструктура, права доступа, libvirt). Поэтому безопасность и надёжность агентов у меня решаются на уровне **harness-enforcement**, а не «промпт попросил вести себя хорошо»:

- Контейнерный sandbox для исполнения произвольного Python, сгенерированного агентом: эфемерные Docker-контейнеры, `--network none`, лимиты memory/cpu/pids, read-only ФС + tmpfs, таймаут с принудительным kill. Абстракция runner'а (dev-режим без изоляции / прод с изоляцией), сессии с TTL, тесты.
- Transport-agnostic агенты: единый контракт, три транспорта поверх одного кода (OpenAI-совместимый API, корпоративный мессенджер, собственный MCP-сервер — StreamableHTTP + OAuth).
- Собственный OIDC/JWT-слой авторизации (Keycloak, JWKS, RS256).

## LLM/VLM как инструмент

- **Zero-shot VLM baseline на реальной задаче:** eval-харнесс Qwen3-VL-235B через API на 7042 размеченных фото повреждений автомобилей — строгий JSON-выход, IoU-метчинг с gold-разметкой. Вывод по цифрам: как замена детектора слаб (macro-F1 0.375), локализация найденного приличная (IoU matched 0.75). Реализацию делал агент под моей постановкой и ревью — одновременно артефакт по применимости VLM и по agentic-инжинирингу. → [projects/damages-vlm.md](../projects/damages-vlm.md)
- **Повседневный agentic-инжиниринг:** Claude Code в ежедневной работе — разработка, ML-эксперименты, аналитика на реальных данных. Кодовая база mosaico спроектирована так, что агенты дописывают код почти без правок: архитектура держит границы через интерфейсы и моки.
- **Разовая выгрузка структурированных данных** из неструктурированных документов (заказ-наряды) для бизнес-аналитики.

## Классический NLP (пре-LLM фундамент)

- **Мультилейбл-классификация тематик клиентских отзывов** (Delimobil, прод): дообучение ru-моделей (sbert/ruBERT/ruELECTRA), focal loss под дисбаланс классов, k-fold, DVC-версионирование. → [projects/nps-text-classification.md](../projects/nps-text-classification.md)
- **Дообучение BERT через TSDAE** (TalentTech): корпус из коротких сообщений требовал нестандартной адаптации; контент-анализ открытых ответов.
- **Тематическое моделирование** (bigartm) в скоринге резюме (JungleJobs).

## Границы опыта (честно)

- Прод-опыт агентов сосредоточен в **одном приложении полного цикла** (два бота на общей основе). Больших мультиагентных оркестраций в проде не строил — задача их не требовала; архитектурные trade-off более сложных схем обсуждаю предметно.
- RAG-контур руками пока не собирал; опыт dense-поиска и эмбеддингов — из рекомендательных систем (faiss).
- Систематический eval качества агентов/генерации не строил; eval на датасетах — повседневная практика, и работа с промптами ведётся тем же циклом eval + debugging.
- Pre-training/файнтюнинг LLM не делал; методологию post-training (SFT/DPO/RLHF/RLVR) изучаю системно по первоисточникам.
